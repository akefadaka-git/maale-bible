**Status:** ORM model slice; migration and production database verification remain pending.

## Models

- Account: opaque UUID primary key, normalized username and E.164 mobile with independent database unique constraints, password-hash field, activation status and creation timestamp. The default status is pending; activation must be explicit after successful OTP verification. Allowed statuses are constrained to pending, active or disabled.
- RegistrationChallenge: pending registration identifiers, password hash, 64-character SHA-256 OTP digest, expiry, non-negative remaining attempts and single-use consumption timestamp. No plaintext OTP field exists.
- AuthSession: account foreign key, token-family UUID, unique 64-character SHA-256 refresh-token hash, expiry, rotation and revocation timestamps.

## Security boundaries

- Model fields do not implement OTP issuance, OTP verification, password hashing, login, refresh rotation or revocation logic.
- Password-hash and OTP-digest values must be generated by reviewed server-side services; never accept client-supplied hashes as trusted credentials.
- OTP digest must be keyed with a server-held secret and compared safely; the secret must not be committed.
- Refresh credentials must be high-entropy random values; only a cryptographic digest is persisted.
- Database constraints are authoritative for account identifier uniqueness. Application pre-checks are not sufficient under concurrency.
- SQLite tests do not prove PostgreSQL locking, isolation or concurrency semantics.

## Verification boundary

Synthetic SQLite model tests cover UUID identity, normalized-identifier uniqueness, OTP digest-only storage and session hash association. A PostgreSQL migration, transaction/concurrency tests, database readiness, provider integration and security review remain outstanding.

No live credentials, user data, source scripture, deployment or production authentication are included.
