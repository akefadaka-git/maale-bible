## Traceability rules

1. Each active requirement has one stable test ID: `TRC-<requirement-id>`.
2. Tests must verify the acceptance criteria verbatim from the approved matrix; implementation tests must exercise domain/repository/UI behavior, not only route presence.
3. Cross-cutting NFR tests may cover multiple journeys, but must report each linked requirement independently.
4. Every requirement must eventually carry test source path, test method, fixture ID, execution run, tested SHA and result.
5. `DEFER-01…06` are explicit negative-scope contracts: they must not appear as working services or live workflows in this offline release.
6. Resource/content-dependent tests remain synthetic until the exact source package and action receive separate Owner authorization.
